1. TOM TAT GIAI PHAP
======================================================================

Google Drive la noi luu file ho so va tai lieu goc:

  Suc khoe gia dinh/                 [rootFolderId]
  |-- family.json                    [familyFileId]
  |-- profiles/                      [profilesFolderId]
  |   |-- {memberId}.json            [profileFileId]
  |-- raw_files/                     [rawFilesFolderId]
  |   |-- {memberId}/                [rawFolderId]
  |       |-- anh, PDF, tai lieu goc
  |-- ai-resources.json              [KHONG LUU API KEY DUNG CHUNG]

Firestore KHONG luu noi dung ho so y te, anh, PDF, Gemini API key hay access token.
Firestore chi luu danh tinh gia dinh, danh sach thanh vien/quyen va cac Drive ID
can thiet de thiet bi moi tim lai dung thu muc. Ban ghi lien ket la lau dai, khong
xoa ngay sau mot lan doc nhu relay mot lan.

Moi thiet bi dang nhap bang tai khoan Google, tra cuu Firebase theo UID, lay
rootFolderId, xac minh quyen Drive, doc family.json, sau do tai profile/tai lieu
theo nhu cau. Local storage/SQLite tren thiet bi chi la cache, khong phai nguon
dinh danh duy nhat.

QUYET DINH BAO MAT BAT BUOC:
Chia se root folder cho mot thanh vien voi quyen Viewer/Editor tren Drive thuong
dong nghia thanh vien do co the doc (va voi Editor co the sua) cac file con duoc
ke thua quyen. Tao raw_files/{memberId} khong tu dong lam folder rieng tu.
Neu moi thanh vien chi duoc xem ho so cua minh, phai cap quyen rieng tren tung
folder/file, hoac dat mot backend lam lop kiem soat truy cap. Khong duoc xem
phan kiem tra role trong UI la bien phap ngan nguoi dung truy cap Drive truc tiep.

CLIENT (web/Android/iOS)

BACKEND (khuyen nghi)
- Firebase Cloud Functions/Cloud Run voi Firebase Admin SDK.
- Chiu trach nhiem moi thanh vien, thu hoi membership, cap nhat link index, audit

FIRESTORE RULES
- Client chi doc link cua UID dang dang nhap.
- Client chi doc thong tin family/member neu la thanh vien active.
- Chi Cloud Functions/nguoi co quyen server moi tao/sua membership va link registry.
- Firestore Rules khong the thay the Google Drive permission. Duy tri ca hai lop.

OAUTH SCOPE
- Google Drive API scope drive.file co quyen hep hon, nhung truy cap file da ton tai
  va duyet folder/file chia se co the can Google Picker va cap quyen chinh xac.
- Neu app can tu dong list/doc/sua moi file trong folder da co san, co the can scope
  Drive rong hon (vi du drive.readonly cho chi doc hoac drive cho doc/ghi). Scope
  rong co yeu cau review/verification va co the phat sinh yeu cau danh gia bao mat.
- Khong mac dinh them scope rong. Prototype tren tai khoan test; chot phuong an
  OAuth, consent screen va verification truoc khi phat hanh.
- Access token la credential ngan han: chi giu trong memory neu co the, khong log,
  khong dua vao URL, khong gui cho ben thu ba.

8.2. Goi Drive API va doc JSON

async function driveRequest(
  token: string,
  url: string,
  init: RequestInit = {}
): Promise<Response> {
  const headers = new Headers(init.headers);
  headers.set("Authorization", `Bearer ${token}`);
  const response = await fetch(url, { ...init, headers });
  // Khong dua response body vao exception/log vi co the chua metadata nhay cam.
  if (!response.ok) throw new Error(`Google Drive API failed: ${response.status}`);
  return response;
}

async function getDriveFileMetadata(token: string, fileId: string) {
  const fields = "id,name,mimeType,trashed,parents,webViewLink,modifiedTime";
  const url =
    `https://www.googleapis.com/drive/v3/files/${encodeURIComponent(fileId)}` +
    `?fields=${encodeURIComponent(fields)}&supportsAllDrives=true`;
  return driveRequest(token, url).then((r) => r.json());
}

async function downloadJson<T>(token: string, fileId: string): Promise<T> {
  const url =
    `https://www.googleapis.com/drive/v3/files/${encodeURIComponent(fileId)}` +
    `?alt=media&supportsAllDrives=true`;
  const response = await driveRequest(token, url);
  const text = await response.text();
  if (text.length > 5_000_000) throw new Error("JSON file exceeds allowed size");
  return JSON.parse(text) as T; // Production: validate schema before using.
}

8.3. Doc folder link tu Firestore va kiem tra

import type { Firestore } from "firebase/firestore";
import { doc, getDoc } from "firebase/firestore";

async function loadFamilyForSignedInUser(
  db: Firestore,
  uid: string,
  familyId: string,
  googleAccessToken: string
) {
  // familyId duoc chon tu cac link cua UID nay; path khop schema Firestore o muc 3.2.
  const linkRef = doc(db, "userFamilyLinks", uid, "families", familyId);
  const linkSnap = await getDoc(linkRef);
  if (!linkSnap.exists()) throw new Error("NO_FAMILY_LINK");

  const link = linkSnap.data() as FamilyLink;
  if (link.status !== "active" || link.familyId !== familyId) {
    throw new Error("FAMILY_UNLINKED");
  }

  const root = await getDriveFileMetadata(googleAccessToken, link.rootFolderId);
  if (root.trashed || root.mimeType !== "application/vnd.google-apps.folder") {
    throw new Error("ROOT_FOLDER_INVALID");
  }

  const manifest = await downloadJson<FamilyManifest>(
    googleAccessToken,
    link.familyFileId
  );
  if (
    manifest.schemaVersion !== 1 ||
    manifest.familyId !== link.familyId ||
    manifest.status !== "active"
  ) {
    throw new Error("FAMILY_MANIFEST_MISMATCH");
  }

  const member = manifest.members.find(
    (item) => item.uid === uid && item.status === "active"
  );
  if (!member) throw new Error("MEMBERSHIP_MISMATCH");

  return { link, manifest, member };
}

Luu y quan trong: Firestore member document la nguon quyen tin cay cua app, con
family.json la manifest Drive can duoc validate va doi soat. Neu client co the sua
family.json theo quyen Drive, khong tu cho phep sua role/UID trong file nay lam co
so nang quyen. Role va membership nen do backend/Firestore quan ly; Admin moi duoc
cap nhat manifest theo quy trinh co kiem tra.

8.4. Liet ke file con trong folder (co pagination)

async function listDriveChildren(token: string, parentId: string) {
  const all: Array<{id: string; name: string; mimeType: string; modifiedTime?: string}> = [];
  let pageToken: string | undefined;

  do {
    const params = new URLSearchParams({
      q: `'${parentId.replace(/'/g, "\\'")}' in parents and trashed = false`,
      pageSize: "100",
      orderBy: "name",
      fields: "nextPageToken,files(id,name,mimeType,modifiedTime,size,webViewLink)",
      supportsAllDrives: "true",
      includeItemsFromAllDrives: "true"
    });
    if (pageToken) params.set("pageToken", pageToken);

    const response = await driveRequest(
      token,
      `https://www.googleapis.com/drive/v3/files?${params.toString()}`
    );
    const page = await response.json();
    all.push(...(page.files ?? []));
    pageToken = page.nextPageToken;
  } while (pageToken);

  return all;
}

Khong scan ca Drive theo ten de tim dung family. RootFolderId/File IDs tu registry
la dau moi; listChildren chi duoc goi tren folder da xac minh quyen.

8.5. Ghi JSON va upload tai lieu

async function updateJsonFile(
  token: string,
  fileId: string,
  value: unknown
): Promise<void> {
  const json = JSON.stringify(value);
  if (json.length > 5_000_000) throw new Error("JSON file exceeds allowed size");

  const url =
    `https://www.googleapis.com/upload/drive/v3/files/${encodeURIComponent(fileId)}` +
    `?uploadType=media&supportsAllDrives=true`;
  await driveRequest(token, url, {
    method: "PATCH",
    headers: { "Content-Type": "application/json; charset=utf-8" },
    body: json
  });
}

async function uploadRawFile(
  token: string,
  parentFolderId: string,
  file: File,
  safeFileName: string
) {
  const allowed = new Set(["image/jpeg", "image/png", "image/webp", "application/pdf"]);
  if (!allowed.has(file.type)) throw new Error("UNSUPPORTED_FILE_TYPE");
  if (file.size > 25 * 1024 * 1024) throw new Error("FILE_TOO_LARGE");

  const metadata = {
    name: safeFileName,
    mimeType: file.type,
    parents: [parentFolderId],
    appProperties: { documentType: "health-source" }
  };
  const boundary = "khosach_" + crypto.randomUUID().replaceAll("-", "");
  const body = new Blob([
    `--${boundary}\r\nContent-Type: application/json; charset=UTF-8\r\n\r\n`,
    JSON.stringify(metadata),
    `\r\n--${boundary}\r\nContent-Type: ${file.type}\r\n\r\n`,
    file,
    `\r\n--${boundary}--`
  ]);
  const url =
    "https://www.googleapis.com/upload/drive/v3/files" +
    "?uploadType=multipart&supportsAllDrives=true&fields=id,name,mimeType,size,createdTime";
  const response = await driveRequest(token, url, {
    method: "POST",
    headers: { "Content-Type": `multipart/related; boundary=${boundary}` },
    body
  });
  return response.json();
}

Upload multipart phu hop file nho/vua. File lon hoac mang yeu nen dung uploadType
resumable, co tien do, resume va cancel. Kiem tra MIME type va kich thuoc ca tren
client va backend neu backend tham gia; khong tin duoi mo rong file.

9. FIRESTORE SECURITY RULES (MOC THAM KHAO)
======================================================================

Rules duoi day minh hoa gioi han doc metadata; can test bang Firebase Emulator va
doi chieu voi schema thuc te. Tuyet doi khong de allow read, write: if true.
Chi Cloud Functions dung Admin SDK duoc phep tao/sua link va membership.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    function signedIn() {
      return request.auth != null;
    }

    function activeMember(familyId) {
      return signedIn() &&
        exists(/databases/$(database)/documents/families/$(familyId)/members/$(request.auth.uid)) &&
        get(/databases/$(database)/documents/families/$(familyId)/members/$(request.auth.uid)).data.status == "active";
    }

    match /userFamilyLinks/{uid}/families/{familyId} {
      allow read: if signedIn() && request.auth.uid == uid;
      allow write: if false;
    }

    match /families/{familyId} {
      allow get: if activeMember(familyId);
      allow list: if false;
      allow create, update, delete: if false;

      match /members/{uid} {
        allow get: if signedIn() &&
          (request.auth.uid == uid || activeMember(familyId));
        allow list: if activeMember(familyId);
        allow write: if false;
      }
    }
  }
}

Rules chi ap dung cho Firestore. Drive permission van cho phep thanh vien mo file
truc tiep bang Google Drive, nen can cap quyen Drive dung voi chinh sach rieng tu.
Cloud Functions phai xac thuc request.auth va kiem tra Admin/member role truoc moi
thao tac; Admin SDK bo qua Firestore Rules.

12. XU LY OFFLINE, TOKEN HET HAN VA LOI
======================================================================

- Offline: cho doc cache neu chinh sach cho phep; ghi mutation queue ma hoa tren
  thiet bi; danh dau chua dong bo. Khi co mang, xac thuc lai membership va revision
  truoc khi gui.
- Token het han/401: refresh/re-auth theo Google Auth flow, chi retry co gioi han.
- 403: phan biet khong co Drive permission, OAuth scope khong du, hoac file bi han
  che. Khong tu ha xuong role Viewer roi gia thanh cong.
- 404: fileId sai/bi xoa/khong con chia se; yeu cau Admin sua registry.
- Firebase link co nhung Drive khong vao duoc: giu membership metadata de Admin sua,
  nhung khong coi la da lien ket.
- JSON sai schema: khong ghi de; bao loi, giu ban cache cu va cho cong cu phuc hoi.
- Retry: exponential backoff + jitter cho 429/5xx/network; khong retry vo han voi
  400/403. Tuong thich idempotency cho thao tac tao file va them thanh vien.
- Khong hien noi dung response API co the chua metadata nhay cam cho nguoi dung/log.

======================================================================
13. MA HOA VA QUYEN RUI RO
======================================================================

Google Drive cung cap ma hoa dich vu, nhung mac dinh khong co nghia la app co ma hoa
dau-cuoi (E2EE). Chu tai khoan co quyen tren Drive co the doc file bang giao dien
Drive/API. Neu can E2EE:
- Ma hoa JSON va file tren client truoc khi upload.
- Quan ly khoa rieng theo gia dinh/thanh vien, co quy trinh them/thu hoi/thiet bi moi.
- Khong luu khoa giai ma trong cung folder Drive.
- Danh gia kha nang tim kiem, xem PDF/anh, AI processing va khoi phuc khoa.

Ma hoa E2EE lam phuc tap viec Admin thu hoi quyen va chia se cho thiet bi moi; can
thiet ke key management rieng, khong tu che bang mot mat khau hard-code trong app.

15. TEST CASE QA TOI THIEU
======================================================================

1. May moi, UID active, Drive permission dung: tu tim root va doc dung profile.
2. Khong co Firestore link: app khong tu chon folder/file dau tien tren Drive.
3. UID khac co email gan giong/da doi email: khong doc duoc family khong duoc cap.
4. Membership revoked nhung local cache con: khong dong bo/ghi moi; xu ly cache theo
   chinh sach va thong bao ro rang.
5. Root folder bi xoa/doi quyen: hien loi lien ket, khong tao family moi tu dong.
6. family.json sai schema, sai familyId, profile memberId khong khop: tu choi su dung.
7. Nguoi Viewer thu ghi profile va upload file: app va Drive deu tu choi.
8. Hai thiet bi sua cung profile: phat hien revision conflict, khong silently overwrite.
9. Upload PDF lon/mang mat ket noi: resume/cancel, khong sinh file trung lap.
10. Phan trang Drive: co hon 100 tai lieu van liet ke du.
11. Admin them member loi nua chung: retry khong tao member/profile/folder trung lap.
12. API key khong xuat hien trong Drive, Firestore, log, bundle public hay crash report.
13. Firestore Rules: UID khong active khong doc family/member; client khong tu nang role.
14. Kiem tra share inheritance: xac nhan thuc te thanh vien doc duoc nhung folder nao.
